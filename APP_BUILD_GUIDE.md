# Turn Math Quest into an Android or Desktop App

This project uses one web game as the source for three installation targets. The original game runs locally without any account, API key, external fonts, or network calls.

## Choose your output

| Output | Command or process | Result |
|---|---|---|
| Test game in a browser | `python3 -m http.server 4173 --bind 127.0.0.1` | Open http://127.0.0.1:4173 |
| Run desktop app window now (Linux + Chromium) | `./launch-linux.sh` | Offline app-style Chrome/Chromium window; needs Chromium installed |
| Installable web app (PWA) | Host project root or `www/` over HTTPS | Browser installation to desktop or Android home screen |
| Android APK | Capacitor + Android SDK | `android/app/build/outputs/apk/debug/app-debug.apk` |
| Linux desktop standalone | Electron Builder | `release/Math Quest-2.4.1.AppImage` and `release/*.tar.gz` (exact name generated by tool) |

**Before replacing existing game files: export your current save using Settings → Export Save Data, then retain the JSON separately. Browser-origin changes require manual import.**

**Important:** The PWA manifest and caching are implemented and statically validated, but installation on a real HTTPS origin still requires testing. The Android debug APK and Electron AppImage require downloading native build dependencies and have not yet been compiled in this delivery.

## A. Use it as a program on a Linux desktop immediately

Extract the ZIP, then:

```bash
cd math-quest
chmod +x launch-linux.sh
./launch-linux.sh
```

The launcher opens `index.html` in an application window through installed Chromium/Chrome. This does not require npm or Android Studio, but does require Chromium/Chrome and is **not** a self-contained executable. Game progress is saved in that browser's local profile.

For a self-contained Linux AppImage, use Electron below.

## B. Build the Android APK on a Linux workstation

Requirements: Node.js 22+, npm, Android Studio with an Android SDK installed. The Android Studio embedded JDK is sufficient. Capacitor 8 requires Android Studio 2025.2.1 or newer. See [Capacitor environment requirements](https://capacitorjs.com/docs/getting-started/environment-setup).

```bash
cd math-quest
node --version
npm install
npm test
npm run android:add
cd android
./gradlew assembleDebug
```

The first run creates the `android/` Gradle project and generates its launcher icons from `assets/logo.png` using `@capacitor/assets`. The APK is expected at:

`android/app/build/outputs/apk/debug/app-debug.apk`

You can install it on your own Android phone by transferring the APK and approving the installation, or use Android Studio/ADB on your connected phone.

On every subsequent game change, run this from the project root *before rebuilding*:

```bash
npm run android:sync
cd android
./gradlew assembleDebug
```

Android release distribution (for Google Play) additionally requires an intentional package identity, private release-signing keys, a release variant, app-store metadata, review and relevant compliance checks. Do not ship a debug APK through an app store.

Alternative: upload this project to a GitHub repository and manually run the included **Build Android Debug APK** GitHub Actions workflow. It uploads the debug APK as a build artifact, assuming GitHub Actions' Android toolchain and dependency downloads work. No repository is automatically changed by this ZIP.

## C. Build a standalone desktop application (Linux)

Requires Node.js 22+, npm and a network connection to install Electron build dependencies on the first run.

```bash
cd math-quest
npm install
npm test
npm run desktop:start
npm run desktop:package
```

The `desktop:start` command opens the desktop program for testing. `desktop:package` requests an offline AppImage and tarball in `release/`. The output is architecture-specific and should be built on the target desktop OS/CPU. Electron Builder packaging has not been executed in this preparation environment because package downloads are blocked.

Windows or macOS installers require their corresponding Electron Builder platform targets and build environment; this project currently has a tested-in-source Linux configuration only.

## D. Host the installable Progressive Web App (PWA)

The PWA requires the game to be served on **HTTPS** (or on localhost during development); opening `index.html` as a `file://` URL does not enable service-worker installation. Upload the contents of the project root or the generated `www/` folder to a static HTTPS host, then open that URL in the phone's browser and choose **Install app** / **Add to Home screen**, as supported by the browser.

To build a production static folder:

```bash
cd math-quest
node scripts/build-web.mjs
```

Host the entire `www/` directory including `manifest.webmanifest`, `service-worker.js`, `css/`, `js/`, and `icons/`. If deploying under a subfolder (such as GitHub Pages under `/repo-name/`), the relative asset paths are preserved.

The service worker caches local static files for offline play. Saves are stored per browser/origin in `localStorage`, not synced across Android/PWA/desktop. Use Settings → Export Save Data, then Settings → Import Save Data to transfer progress manually.

## E. Run verification

```bash
node --version
npm test
npm run build
CHROMIUM_BINARY=/usr/bin/chromium python tests/browser_smoke.py
CHROMIUM_BINARY=/usr/bin/chromium python tests/browser_regression.py
CHROMIUM_BINARY=/usr/bin/chromium python tests/browser_grade_subjects.py
# Hosted PWA offline check (requires Chromium loopback access):
CHROMIUM_BINARY=/usr/bin/chromium python tests/browser_offline.py
```

No `npm install` is required for these particular verification commands, because the test runner and web asset copier use Node.js built-ins. Tests cover question answer invariants, profile/XP/rewards, old-save migration, independent shop ownership, timeout advancement and offline-asset manifest integrity.

Optional browser smoke testing (requires Python Playwright and Chromium) is described in `tests/browser_smoke.py`. Real installability, application signing, Gradle and Electron packaging must be verified on the target platforms.

## Data and distribution

Player profiles and progress currently live in each app installation's browser/webview storage. There is no user account server or cloud sync. The game is educational content and its numerical answers should undergo additional independent pedagogical review before a public launch.
